# Quickstart

## Download the final zip

If you want to use the final dataset in the simplest format with all of the .txt files, download it from the releases (more details under the Export Data section).

## About the dataset

The dataset simulates a company called "Redwood Inference" that provides AI model inference as a service. The dataset consists of ~450,000 documents spread across the following sources:

- Slack: ~225,000 docs
- Gmail: ~120,000 docs
- Linear: ~35,000 docs
- Google Drive: ~25,000 docs
- Hubspot: ~15,000 docs
- Fireflies: ~10,000 docs
- GitHub: ~8,000 docs
- Jira: ~6,000 docs
- Confluence: ~5,000 docs

The dataset provides broad coverage across key areas of business activity including (but not limited to) planning, engineering, documentation, sales, customer success, internal discussions, emails, and more.

## Repo Layout

`export_data` contains the final files of the dataset for export.
`generated_data` contains the raw document files in JSON format with rich metadata that can be exported in different ways.
`src` contains the code files to run the data generation pipeline.
`generation_cache` is populated during the data generation process for use between different steps.
`answer_evaluation` is a convenience directory with explanations on how to run eval on your final results.

### Questions File
The dataset comes with 500 questions broken up into 10 categories:

| # | Category | Count | Description |
|---|----------|-------|-------------|
| 1 | Basic | 200 | Simple questions with a single ground truth document. |
| 2 | Semantic | 100 | Similar to Basic but more roundabout, with less keyword/phrase overlap and without giveaway-type keywords. |
| 3 | Single Doc Multi-hop | 50 | Requires combining information from several distant sections of a single longer document. |
| 4 | Project Related | 40 | Aggregate knowledge from related documents from a single project/initiative within the company. |
| 5 | Constrained | 30 | Questions with multiple relevant documents but with qualifiers that disqualify all but one answer. |
| 6 | Conflicting Info | 20 | Questions where documents directly contradict each other. Requires the system to give a complete and correct answer. |
| 7 | Completeness | 10 | Questions that require fetching all relevant documents (no more than 10) to be able to provide a correct answer. |
| 8 | Misplaced | 20 | Questions requiring finding documents which are not optimally placed within the knowledge base. |
| 9 | High Level | 10 | High level questions where the answer is not located in any single document. Note: these do not have any ground truth documents. |
| 10 | Info Not Found | 20 | Questions where the answer is not available. Note: these do not have any ground truth documents. |

Additionally 100 questions are provided outside of the benchmark which require parsing the metadata of the documents to answer correctly.
These are not included in the standard set as different systems may parse metadata fields differently and the export functions provided in this code repository drop these by default.
The intent of the export is to make the dataset as easy to use for researchers and developers as possible. To run your own exports and include the metadata, refer to the Developer Guide.

For a detailed explanation on the generation/validation of these questions, refer to the paper here.

### Export Data

The `export_data` directory contains the final zip files for the generated dataset. The documents are represented in simple .txt formats inside of the zip files.
The files are prefixed with the data set UUID, abbreviated as `dsid_`, followed by a SHA and finally by the actual file name.
The file name is just a semantic name generated by the LLM and does not necessarily represent any real information.
The text file contents start with the title of the document followed by all of the content fields identified by the LLM.

An export of the entire dataset is provided as `export_data/all_documents.zip`. This contains all of the documents and their corresponding file paths.
When unzipped, the top level will contain the different source types and within each will be a directory structure that mimics the layout of documents within the source type.

A separate set of exports is provided as `export_data/google_drive_slice_0001.zip` etc. which is broken down by source type and includes up to 5000 documents max per zip.
This is done to make it easier to use subsets of the data for different use cases. The files under this format do not contain the directory structure.

## Generate your own data
One of the key considerations of this repository is to make it easy for teams to generate their own datasets which simulate company internal data.
To do this, delete the directories `export_data`, `generated_data`, and `generation_cache` and run through the different data generation scripts.

The stages of generation are broken down into:
1. Generating the base data (`src/data_scripts/stage_1_generate_clean_data`)
2. Adding noise (`src/data_scripts/stage_2_add_noise`)
3. Generating questions (`src/data_scripts/stage_3_generate_questions`)
4. Exporting the dataset (`src/data_scripts/stage_4_data_export`)

Each stage has provided scripts to be run in order to generate the data. Some steps will require interactions between the user and LLM to guide the direction of the generation.

For more details, check out the developer guide.
